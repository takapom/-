# As-Is / To-Be 認識

## 目的

既存案を、PoC 計画ではなく学術的に意味のある研究計画へ引き上げるために、現在の見え方、到達すべき見え方、差分を整理する。

使用した発想フレームは、`brainstorming-research-ideas` のうち次の5つである。

- Problem-First vs. Solution-First: 何の問題を解く研究かを先に固定する
- Abstraction Ladder: ドローン固有実装から一般化可能な設計原理へ上げる
- Tension and Contradiction Hunting: 自然言語の柔軟性と物理制御の安全性の緊張を研究機会にする
- Failure Analysis and Boundary Probing: 失敗条件の体系化を貢献に含める
- Composition and Decomposition: LLM、ミッション仕様、検証器、SITL、実機制御を分離して評価可能にする

## As-Is: 現在の案

現在の `hogehoge.md` は、次のような構成になっている。

- 非専門家が自然言語でドローンの経路や制約を変更できるようにする
- Claude Code / Codex で自然言語から制御コードまたは高レベル指令を生成する
- AI ハーネスで制約付与、状態保持、ログ解釈、評価、再生成を行う
- ArduPilot SITL、Raspberry Pi、Pixhawk、実機ドローンを段階的に使う
- 評価指標として構文エラー、実行時エラー、安全制約違反、タスク成功率、軌道逸脱などを見る

この案の強い点は、段階的検証と安全評価を含んでいること、また「LLM をそのまま実機へ接続しない」という設計意識があることにある。

一方で、研究としては次の弱さが残る。

- 「LLMでドローンを制御する」だけだと既存研究との差分が弱い
- AI ハーネスの定義が曖昧で、何を発見する研究なのかが見えにくい
- Codex と Claude Code の比較が中心に見えると、モデル依存・時点依存の評価になりやすい
- 自然言語から「コード」を直接生成するのか、「ミッション仕様」を生成するのかが混在している
- 低レベル制御、経路計画、安全検証、ログ修復の責務境界がまだ固定されていない
- 実機検証が強調されすぎると、研究貢献より実装デモに見えやすい

## To-Be: 研究として目指す姿

研究の主題は、次のように置き換える。

> 自然言語によるUAVミッション変更を、状態保持・制約検査・シミュレーション評価・ログに基づく修復を通じて、安全制約付きの実行可能ミッションへ変換する AI ハーネスの設計条件を明らかにする。

この置き方にすると、学術的な意味は次の4点に整理できる。

1. 自然言語の曖昧さと、物理システム制御に必要な決定性・検証可能性のギャップを扱う
2. LLM を低レベル制御器ではなく、ミッション仕様生成・修復・説明に限定する境界設計を扱う
3. 直接コード生成ではなく、中間表現、検証器、SITL、実行ログを含む閉ループハーネスを評価する
4. 成功例だけでなく、失敗の分類、制約違反、再生成、人的介入を測ることで設計原理を抽出する

## 研究としての中心課題

中心課題は「自然言語で飛ばせるか」ではなく、次の問いにする。

> どのようなハーネス構造を置けば、LLM が生成する自然言語由来のミッション変更を、UAV の安全制約を破らずに安定して実行可能なミッションへ変換できるか。

この問いは、単なるシステム実装ではなく、次の設計変数を比較できる。

- 直接コード生成 vs. 中間ミッション仕様を介した生成
- 状態保持なし vs. 状態保持あり
- 制約検査なし vs. 静的制約検査あり
- シミュレーション評価なし vs. SITL によるゲートあり
- 失敗ログを捨てる方式 vs. 失敗原因を分類して修復する方式
- LLM を低レベル制御に近づける方式 vs. LLM を高レベル計画・修復に限定する方式

## 差分

| 観点 | As-Is | To-Be |
| --- | --- | --- |
| 研究名の印象 | LLMでドローンを制御するPoC | 安全制約付き自然言語UAVミッション変換ハーネスの研究 |
| 主な問い | 自然言語でドローンを動かせるか | どのハーネス構造なら安定・安全・再現可能になるか |
| 生成対象 | 制御コードまたは高レベル指令が混在 | 型付きミッション中間表現を第一生成物にする |
| LLMの位置 | コード生成器・制御補助 | ミッション仕様生成、失敗解釈、修復提案 |
| 安全性 | 実行前後に制約を確認 | 検証器、SITL、実行ゲート、ランタイム監視で層化 |
| 比較対象 | Codex vs Claude Code | ハーネス構成のアブレーション。モデル差は副次条件 |
| 貢献 | 動くプロトタイプ | アーキテクチャ、評価ベンチ、失敗分類、設計原理 |
| 実機の役割 | 最終的な成功デモ | SITLで得た知見の限定的な妥当性確認 |

## 既存研究との差分の取り方

関連研究には、すでに自然言語、LLM、VLA、UAV計画、安全検証を組み合わせる流れがある。したがって、本研究は「自然言語でUAVを制御する初の研究」として主張すべきではない。

差分は次の方向で取る。

- VLA や模倣学習ではなく、コード生成型・エージェント型 LLM を安全に物理実行へ接続するハーネスに焦点を置く
- 一回の命令解釈ではなく、自然言語によるミッション変更、失敗ログ、再生成を含む閉ループに焦点を置く
- 新しい軌道最適化手法より、どの層で LLM を止め、どの層で決定的検証へ渡すべきかを明らかにする
- 実機性能の最高値ではなく、制約違反、出力分散、修復回数、人的介入という運用信頼性を評価する

## 2文ピッチ

UAV の自然言語操作は非専門家にとって有用だが、LLM 出力をそのまま物理システムへ接続すると、曖昧な指示、出力分散、危険なAPI呼び出し、過去の失敗文脈の喪失により、安全で再現可能な運用が難しい。

本研究では、自然言語指示を型付きミッション仕様へ変換し、制約検査、SITL評価、ログ解釈、修復を通じて実行候補を段階的に絞り込む AI ハーネスを設計・比較し、どの構成要素がUAVミッション変換の安全性と安定性に効くかを明らかにする。
